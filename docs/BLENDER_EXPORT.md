# Blender → glTF 2.0 export guide

The engine consumes **glTF 2.0 binary (`.glb`)** only. The loader supports
meshes, materials + textures, node hierarchies, skins, animation clips and
`KHR_lights_punctual`, plus the level conventions below.

## Coordinate system

glTF 2.0 is Y-up, right-handed, 1 unit = 1 meter. The engine uses the same
convention (camera looks down −Z, +Y is up), so **no axis conversion is
applied at load time**. A model authored facing +Z in glTF faces the player
when the player looks down −Z.

## Export settings (File → Export → glTF 2.0)

| Setting | Value |
| --- | --- |
| Format | `glTF Binary (.glb)` |
| Include → Selected Objects | on (export only the wanted set) |
| Include → Custom Properties | **on** (needed for extras) |
| Transform → +Y Up | **on** (default) |
| Transform → Apply Modifiers | on |
| Geometry → Normals | on |
| Geometry → Tangents | on |
| Geometry → UVs | on (UVMap / uv0) |
| Geometry → Vertex Colors | off unless used |
| Geometry → Triangulate | on |
| Geometry → Loose Edges/Points | off |
| Material → Export | on |
| Images | `Automatic` (embedded in .glb) |
| Animation → Export Animations | on |
| Animation → NLA Strips / All Actions | one action per clip |
| Animation → Sampling Rate | 1 (or leave "Always Sample Animations" on) |
| Skinning → Export Deform Bones Only | on |
| Skinning → Add Leaf Bones | off |
| Skinning → Max Bone Influences | **4** (engine limit) |

Apply object transforms (`Ctrl+A` → All Transforms) before export unless a
non-identity node transform is intentional level placement.

Scene scale: 1 Blender unit must equal 1 meter. Check the unit settings and the
object dimensions; glTF does not carry a global unit scale.

## Vertex data

Vertices carry position, normal, uv0, tangent, joints (4) and weights (4).
The exporter must write `JOINTS_0`/`WEIGHTS_0` for skinned meshes; missing
normals/tangents are generated by the loader, but exporting them gives the
intended shading.

## Node-name conventions (levels)

| Prefix | Meaning |
| --- | --- |
| `COL_` | Invisible collision geometry. The node's mesh bounds become an `AABBCollider`; nothing is rendered. |
| `SPAWN_` | Spawn marker. Becomes a `SpawnPoint`; the suffix is the tag (`SPAWN_player`). The node's −Z is the facing direction. |
| `TRIGGER_` | Trigger volume. The node's mesh bounds become a `TriggerVolume` (local box, world AABB refreshed from the hierarchy, so the level root's placement/rotation/scale applies); the suffix is the tag. |

All other mesh nodes become renderable entities (one child entity per
material primitive). Node `extras` become an `EntityExtras` key/value map
(use Blender's Custom Properties). `KHR_lights_punctual` point and spot lights
become `PointLight` / `SpotLight` components; directional lights are ignored by
the current forward renderer.

A `.glb` can be loaded as a whole level (`LevelBuilder::instantiate`) or as a
prefab by placing its root at any transform. Skinned meshes are rendered with
the entity's world matrix as the model matrix, and glTF's mesh-node space
skinning inverse cancels that transform exactly once.

## Animation

- Name each action after the clip (`idle`, `walk`, `attack`, ...); exporters
  typically emit the action name as the glTF animation name.
- Clip playback is time-based; `Animator::play("walk", 0.25f)` crossfades in
  over 0.25 s. Looping is the caller's choice (`loop=true` by default).
- Animation events (footsteps) come from the animation's glTF `extras`:

```json
{
  "events": [
    { "time": 0.35, "name": "footstep" },
    { "time": 0.85, "name": "footstep" }
  ]
}
```

`Animator::onEvent` fires them while the clip plays, including across loop
wraps. Add `AnimationClip::events` manually in code if authoring JSON extras in
Blender is inconvenient.
